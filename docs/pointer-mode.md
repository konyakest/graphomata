# Pointer Mode — 方案（Python / 网页端）

> 目标：去掉 worker。变量就是节点引用，一切操作都在节点上。
> 计分维度从「ops」换成「**峰值同时存在的引用数**」。
> 范围：只做网页端的 Python 子集；桌面 C++/Python 维持 worker 模式，暂不跟进。
> 状态：**已实现**，入口 `web/ptr/`（`web/index.html` 会跳转过去）；worker 模式的网页入口已删除。

---

## 1. 运行时模型

- 图：有向图，节点有 id，边唯一、不允许自环。
- 引用（ref）：一个「变量 → 节点或 None」的绑定，或者一个临时值。
- 没有 worker、没有 home、没有寄存器字母，也没有「站在节点上」这个概念。
- **引用才是根，边不是。** GC 从所有 active 引用出发，**沿出边**做有向可达标记；
  没有被标记到的节点回收（连同边）。
- 根 = 值不为 `None` 的变量 + 当前活着的临时值。
- **`return` 之后函数作用域结束**：局部变量（包括参数）全部释放，只有返回的节点作为根活下来。
  所以“return 原链”不会保留原链，除非另有引用。
- 因此：两个节点互相指着（环）但没有任何变量引用时，照样一起回收（没有根，走不到）。
- GC 在每次赋值、`return`、以及每一步之后执行。

### GC 细节

```python
a = Node()
b = Node()
a.link(b)      # a -> b，单向边
b = None       # 根还有 a；b 能沿边从 a 走到 -> a、b 都不回收
a = None       # 根没了 -> a、b 一起回收
```

```python
a = Node()
b = Node()
a.link(b)
b.link(a)      # a <-> b，双向边
b = None       # 根还有 a；b 和 a 同一个弱连通分量 -> 不回收
a = None       # 根没了 -> 一起回收
               # 注意：按“入边计数”的 ref-counter 会认为它俩还活着，
               # 但这里判的是“从变量引用能不能走到”，所以环也会被回收
```

> **有向可达的后果**：`s = s.next()` 之后，如果没人再引用旧的 `s`，旧节点就回收了——
> 因为沿出边走只能向前，回不到前驱。想保住整条链，就在开头把 `s` 存一份（`head = s`），
> 让根留在头上。这也是第 4 关必须返回新头（而不是原来的 `s`）的原因。

## 2. 语言（Python 子集，严格版）

只允许：

| 语法 | 说明 |
| --- | --- |
| `def solve(s):` | 唯一的函数定义，参数是起始节点 |
| `return expr` | 返回新的起始节点 |
| `a = expr` | 单目标赋值，重新绑定引用 |
| `if cond:` / `elif` / `else:` | 条件 |
| `while cond:` | 循环 |
| `for _ in range(n):` | 计数循环，`n` 是整数常量（≤ 10000）；`_` 不能当变量用 |
| `break` / `continue` / `pass` | 照常 |
| `Node()` | 新建节点，返回临时引用 |
| `a.next()` | 随机一个子节点；没有子节点返回 `None` |
| `a.link(b)` / `a.unlink(b)` | 加边 / 删边（语句形式） |
| `a is None` / `a is not None` | 判断是否为空 |
| `a is b` / `a is not b` | 判断是否同一个节点 |
| `and` / `or` / `not` | 布尔组合 |

不允许：

- 除 `solve` 以外的 `def`、递归；
- 整数、字符串、布尔字面量、list/dict/tuple、下标、切片；
- `print`、`import`；
- 函数调用（除了 `Node()` 和上面的方法）；
- 增强赋值、元组解包、链式赋值。

### 示例

```python
def solve(s):
    s.link(Node())
    return s
```

```python
def solve(s):                 # copy 一条链
    head = Node()
    ss = head
    while s.next() is not None:
        ss.link(Node())
        ss = ss.next()
        s = s.next()
    return head
```

> 条件里的 `s.next()` 和 body 里的 `s.next()` 是两次调用、各算 1 步、各占一个临时引用。
> 链上出度是 1，两次一定走同一个邻居，所以这个写法成立；**分叉图上不能这么写**。
> 对照的通用版本（只调用一次，多一个 `nxt`）：
>
> ```python
> def solve(s):
>     head = Node()
>     ss = head
>     while s is not None:
>         nxt = s.next()
>         if nxt is not None:
>             ss.link(Node())
>             ss = ss.next()
>         s = nxt
>     return head
> ```

## 3. 步进与引用计数

### 3.1 什么算一步

| 操作 | 步数 |
| --- | --- |
| `Node()` | 1 |
| `.next()` | 1 |
| `.link(b)` | 1 |
| `.unlink(b)` | 1 |
| `x = y` / `x = None`（纯 move） | 1 |
| `x = <外层调用>`（如 `x = b.next()`） | 与这次调用**合并**，不额外加步 |
| `for` 的循环头 / `range(n)` | 0（只有 body 里的操作算步） |
| `is None` / `is not None` / `is` / `is not` | 0 |
| `return` | 0（但会改变 active 集合） |

赋值会吸收它最外层的调用：`x = b.next()` 是 **1 步**，`x = b.next().next()` 是 **2 步**（第一个 `next` 一步，第二个和赋值合并）；
`x = Node()` 也是 1 步。每执行一步，更新图、做一次 GC、记录一帧。

### 3.2 active 与峰值

- **active 引用** = 值不为 `None` 的变量名 + 当前活着的临时值。
- `refs = len(active)`，**峰值** = 全程 `refs` 的最大值。
- 赋值后也要重新统计（`b = a` 会让 active +1）。

### 3.3 临时值

- `Node()` 产生临时值，显示为 `Node()`；
- `a.next()` 产生临时值，显示为 `a.next()`；
- 对临时值继续 `.next()`，**原地移动这个临时值**，不新增引用，显示名变成 `a.next().next()`；
- 临时值被 `link` / `unlink` 当参数用掉、或者被 `is None` 比较掉之后，立刻销毁；
- 赋值会和最外层的调用合并：`a = b.next()` 只有 1 步，帧里直接显示 `a`；
  `a = b.next().next()` 的第一个 `next` 仍有一个临时帧，第二个和赋值合并；
- 别名（`a = b`）和清空（`a = None`）是 1 步 move；
- 语句结束时还没被用掉的临时值，销毁。

### 3.4 你给的例子，按这套规则

```python
a.next().next().next()
```

| 时刻 | active | 峰值 |
| --- | --- | --- |
| 第 1 步后 | `a`、`a.next()` | 2 |
| 第 2 步后 | `a`、`a.next().next()` | 2 |
| 第 3 步后 | `a`、`a.next().next().next()` | 2 |

→ 3 步，峰值 2。

```python
b = a.next()
```

- 1 步（`next` + 赋值合并）：帧里直接是 `a`、`b` → 2；
- **步数 1，峰值 2**。

```python
b = a.next().next()
```

- 第 1 步（`next`）：`a`、临时 `a.next()` → 2；
- 第 2 步（`next` + 赋值合并）：`b` 落到第二个节点上 → 2。
- **步数 2，峰值 2**。

```python
for _ in range(3):
    s.link(Node())
```

- 循环头 0 步；body 每次 `Node()` + `link` = 2 步；
- 总共 6 步。

```python
a = b
```

- 1 步（move）：`a` 也指向 `b` 的节点；
- 峰值 +1（原来只有 `b`，现在 `a`、`b` 两个引用）。

```python
s.link(Node())
```

- 第 1 步：`s`、临时 `Node()` → 2；
- 第 2 步：`link` 用掉临时值 → 只剩 `s` → 1。
- **步数 2，峰值 2**。

## 4. API

| 写法 | 语义 | 步 |
| --- | --- | --- |
| `Node()` | 新建节点，返回临时引用 | 1 |
| `a.next()` | 从 `a` 随机选一条出边，返回目标节点；没有出边返回 `None` | 1 |
| `a.link(b)` | 加边 `a → b`；`a`、`b` 都不能是 `None` | 1 |
| `a.unlink(b)` | 删除边；边必须存在 | 1 |
| `a is None` | 是否为空 | 0 |
| `a is b` | 是否同一个节点 | 0 |
| `return x` | 返回新的起始节点；`x` 为 `None` 视为失败 | 0 |

错误：

- 对 `None` 调 `.next()` / `.link` / `.unlink` → 运行时错误；
- `link` 自环、重复边 → 错误；
- `unlink` 不存在的边 → 错误；
- 步数超过关卡上限 → 失败（防死循环）。

## 5. 判题

一关包含：

```json
{
  "id": "03-copy",
  "start": 0,
  "graph": { "nodes": 4, "edges": [[0,1],[1,2],[2,3]] },
  "goal": {
    "iso": { "nodes": 4, "edges": [[0,1],[1,2],[2,3]] },
    "return_new": true
  },
  "max_refs": 4,
  "max_steps": 40,
  "seeds": [1, 2, 3]
}
```

`return_new` 要求返回的节点不是关卡初始节点：否则 `return s` 什么都不做也能满足形状。

### 多组测试点

每关的 `graph / goal / max_refs / max_steps` 是第一组测试数据；`cases` 里是额外的测试点，
可以换不同大小的图：

```json
{
  "graph": { "nodes": 4, "edges": [[0,1],[1,2],[2,3]] },
  "cases": [
    { "label": "测试点 2", "detail": "6 节点链",
      "graph": { "nodes": 6, "edges": [[0,1],[1,2],[2,3],[3,4],[4,5]] },
      "goal": { "iso": { "nodes": 6, "edges": [[0,1],[1,2],[2,3],[3,4],[4,5]] }, "return_new": true },
      "max_refs": 4, "max_steps": 52, "seed": 1 }
  ]
}
```

- 所有测试点都在下拉框里直接可选；
- 运行 / 单步只跑当前选中的测试点；
- **提交**跑全部测试点，全过才算过关；
- 失败会自动切到第一个错掉的测试点，显示它的图，方便对错数据调试。

> 反转关已经删掉：无标记的链反转后和原图同构，纯形状判题分不出来；加 tag 又只是个玩家碰不到的判题锚点。
> 要恢复的话，得给这一关单独的判题方式（精确边或 tag）。

- **通过**：最终图与 `goal.iso` 同构，并且 `return` 的节点不是 `None`；
- **分数**：`peak_refs`（越小越好），`steps` 作为并列时的 tie-break；
- 超过 `max_refs` 直接判负（“这关不能用超过 2 个引用”是题面的一部分）；
- 多 seed：每个 seed 都通过才算过（`next()` 是随机的）。

`max_refs` 就是这一关的“寄存器预算”。`max_steps` 只用来防止死循环，不进入分数。

## 6. 渲染

- 变量或临时值 = 节点上的一个标签（tag），带颜色；
- 值变成 `None` 的变量：标签消失，颜色保留（下次重新 active 可以换色）；
- 临时值标签用表达式文本：`Node()`、`a.next()`、`a.next().next()`；
- 临时值被赋值给变量时，标签直接变成变量名（中间表达式标签消失）；
- 每一步一帧：先显示新产生的临时值，再显示赋值后的变量名（同一帧内完成，下一帧只剩变量名）；
- 节点本身不再显示 id，用颜色区分（沿用现在的做法）；
- 顶部显示：`refs 2 / max 3`、`steps 12`、峰值。

颜色：

- 每个变量名分配一个固定色；
- 临时值按表达式分配一个色；
- 变量 inactive 再 active 时允许换色。

这条线的主题是**图灵完备**：图就是内存。链/环是状态，复制是分配新内存，双向指针是
可回退的栈，树和梯子是可递归/并行的结构；配上 `while`、`is` 和可无限增长的图，
这套机器能编码任意计算。前 10 关是这条路的入口。

> `max_refs` 是初值，实际用参考解跑出来再定（一般取参考解峰值）。

- 第 5 关用 `next()` 的随机性：每次 `next()` 走的邻居不同，程序必须对所有 seed 成立；
- 原来的“随机搜索”关不适合这个模型（没有第二个 cursor），换成“拆环”。

## 9. 已定的取舍

1. **只有 `solve` 一个函数**：没有 `def`、没有递归，局部变量不会跨调用帧，峰值统计简单。
2. **只有 Node/None**：没有整数，所以没有 `for`/`range`；循环只能沿图走。
3. **`is` 可以比较两个节点**：方便写“两个引用是否同一节点”。
4. **`next()` 是随机的**：保留原作的不可预测性；多 seed 判题。
5. **临时值原地移动**：`a.next().next()` 只占一个引用，峰值才是 2。
6. **GC 只回收孤立节点**：有边的节点永远活着，所以“建完就丢”是安全的。
7. **`max_refs` 是硬上限**，`max_steps` 只防死循环。
